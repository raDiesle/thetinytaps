# Code and architecture review, 17 November 2026

Every finding of the repository review (six read-only reviewers: agent docs, build and loading, SEO, shared code,
games, tools/tests/CI), with its evidence and the fix proposed, so nothing is lost when a finding is skipped for now.
A later session can pick any open item by its id ("mach R-P4"). This file is not loaded by itself: read it only when
you work on one of its items, and set the item's status in the same commit.

Status: **DONE** fixed on the review branch · **PART** started, see the note · **OPEN** not started ·
**ASK** needs the owner's decision first · **NO** looked at and deliberately left.

Line numbers are those of 17 November 2026; grep the named function when they have moved.

## How to work on these cheaply

- One item (or one group touching the same files) per session, in a subagent on a cheaper model where the item is
  mechanical (marked `mech`).
- Items marked `browser` need a look in the preview after the change, items marked `build` a `bun run build` and a
  look at `out/`.
- The measurements came from throwaway scripts; the method is described with each item so they can be redone.
- Several subagents in one worktree: each owns its files, none commits. Before committing their work by pathspec, see
  that the index is empty (`git diff --cached --stat`): a subagent's `git rm` or `git mv` stays staged and went into
  another group's commit once, which left that commit unable to build.
